# 船舶纵向下水计算：从邦戎资料到可复核的工程报告

> **公开范围与版权提示**：这是技术交流稿，不是投稿全文。配图为原创示意，代码仅处理虚构记录。软件本体、求解器、授权机制、项目数据库及内部报告不随本文发布；本文及站点模板的许可均不构成对该软件的授权。如需取得软件、源码或部署许可，请另行联系相应权利人。下文不构成实际下水作业的计算书或放行依据。

## 摘要

纵向下水计算要回答的不只是「船能不能浮起来」。船体尚在滑道上时，支承反力、入水姿态和速度都在变化；转入浮态后，原先有效的接触约束也不再成立。本文从软件实现角度说明怎样把船体、滑道和水域资料放到同一套基准上，按阶段处理浮力与支承，再将速度、滑板压力和河床净空关联到对应工况。最后区分程序验证、样例复算和实船验证，说明报告能支持什么结论，以及哪些问题仍需人工复核。

**关键词：** 纵向下水；邦戎表；尾浮与全浮；滑板压力；河床净空；工程复核

## 1. 问题定义：先确定比较的是哪一个工况

输入可分为三组：

| 输入 | 在计算中的用途 | 首先复核什么 |
| --- | --- | --- |
| 下水重量与重心 | 建立重量及其作用位置 | 是不是同一个下水装载状态；质量与力有没有混用 |
| 邦戎表与剖面站位 | 描述不同浸深下的横剖面浸水面积 | 站位方向、吃水基准及数据覆盖范围 |
| 滑道、潮位与河床 | 确定支承几何和可用水域 | 纵向原点、高程基准，以及测量与计划工况能否对应 |

把数据导入软件不等于数据已经可算。例如，潮位和河床高程如果不在同一基准下，两者相减即使得到一个小数位很多的结果，也不能解释为净空。重量、重心或滑道条件变更后，应把依赖这些输入的旧结果视为过期，避免报告把两套工况拼在一起。

## 2. 方法：用浸水剖面重建浮力，随阶段更换约束

邦戎表可以看作一组「站位—浸深—浸水面积」资料。对某一船体姿态，先看各站位的浸深落在表的什么位置，再把对应面积沿船长汇总成排水体积。浮力的基本关系是 **浮力 = 水密度 × 重力加速度 × 排水体积**。面积的纵向分布还影响浮力的作用位置，不能只看体积大小来判断船首、船尾的受力变化。

这里真正需要区分的是支承条件：

- **受约束滑移。** 船体仍由滑道支承，姿态不能直接套用自由漂浮条件。随着船尾入水，浮力逐渐分担重量，支承及其作用位置随之变化。
- **尾浮。** 艉部开始脱离支承，但艏部仍可能受支承。此时要关注支承重新分配后的局部受力；尾浮不等于全船已经自由漂浮。
- **全浮。** 滑道不再提供支承，在该模型下转为检查由浮力承担重量时的姿态与平衡。全浮也不意味着速度、净空等专项检查可以省略。

## 3. 实现逻辑：围绕同一滑程组织三类检查

**速度。** 软件沿滑程更新速度估计，考虑重力作用、摩擦和阻力的变化。用滑程对齐速度和姿态，复核人员才能追问「这个速度出现在入水前还是浮起后」。这里的阻力等输入含经验成分，不能把递推曲线等同于完整的瞬态水动力仿真。

**滑板压力。** 总反力不能直接解释为局部压力。接触范围和载荷分配随姿态改变，尾浮附近尤其不能沿用全长均匀受压的想象。结果应同时说明相应的支承阶段和位置，而不是只摘录一个最大值。

**河床净空。** 把各个离散姿态的船底位置放进同一纵向与高程基准，再比较同一位置的船底包络与河床。最低包络用来定位需要复核的区域，不等于已经获得可直接施工的清淤线。滑程采样、测深覆盖和潮位选择都会影响这个判断；资料缺失的区段不应默认安全。

复核时，三项检查应对应同一工况、滑程轴和输入版本。报告需要保留曲线、关键状态、异常及适用范围：当结论被质疑时，可以追溯是哪个输入、哪一个阶段或哪一段数据需要重查。

## 4. 应用示例：将已复核的记录整理成清单

下面只演示**报告后处理**：把两条手工构造的记录写成 CSV，供复核人员回看。字段是本文自定义的展示格式，不是原软件的数据结构或调用接口。「待复核」是示例中预先填写的人工标签，不由程序计算。

```python
import csv
import sys

# 虚构记录：不含船型、滑程、工程阈值或原项目字段。
records = [
    {"编号": "DEMO-A", "阶段": "受约束滑移", "复核备注": "核对输入版本"},
    {"编号": "DEMO-B", "阶段": "尾浮", "复核备注": "待人工复核支承状态"},
]

writer = csv.DictWriter(sys.stdout, fieldnames=["编号", "阶段", "复核备注"])
writer.writeheader()
writer.writerows(records)
```

这个例子可以直接运行，但不会计算浮力、速度、压力或净空，也不会给出「可以下水」的判断。它只示范如何把阶段与复核意见放在同一行，便于从报告返回原工况。

## 5. 验证结果与适用边界

现有资料应按三类验证分别说明，不能混成一句「已验证」：

| 证据 | 公开结论 | 不能据此得出 |
| --- | --- | --- |
| 核心及边界测试 | 打包复核的 36 项核心测试通过；全量发现时另有 3 个测试模块因缺少界面依赖未执行 | 全量测试已通过，或整个界面已经验收 |
| 解析简化算例与样例复算 | 可用已知解检查基础几何与浮力链条，也有随附样例的程序复算记录 | 样例结果就是实船测量，或可迁移到任意船型与船台 |
| 实船与现场验证 | 资料未提供同步实船观测，也未完成整套报告的重新生成与视觉验收 | 已完成独立实船验证或取得工程放行结论 |

当前方法以二维、准静态姿态为主，无法替代完整的三维水动力、横向稳性及结构核查。邦戎资料覆盖不足、外推和离散步长都可能影响结果；摩擦、阻力和潮位条件也需要独立依据。实际作业应由具备相应资质的工程人员根据现场资料、适用规范及审批程序复核。

## 6. 结论

这套实现的价值，是把「当前用的是什么输入」「船现在由什么支承」「哪里还需要复核」串成可追溯的计算链。公开版保留这条工程逻辑，同时省略求解器实现、内部参数、测试夹具和真实项目数据。读者可以理解怎样组织复核，但不能把这里的示例当成软件内核、计算成果或作业许可。
